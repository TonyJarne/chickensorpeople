# Contributing to Chickens vs People in Europe

Thank you for your interest in contributing to this project! This document provides guidelines and instructions for contributing.

## Ways to Contribute

### 1. Data Updates
- Update data with new FAOSTAT or Eurostat releases
- Add data for additional European countries
- Include historical trend data
- Contribute translated data sources

### 2. Analysis & Insights
- Contribute regional analysis
- Add economic impact studies
- Provide agricultural sector research
- Share policy implications

### 3. Code Improvements
- Enhance the interactive visualization
- Fix bugs or improve performance
- Add new features (charts, filters, exports)
- Improve mobile responsiveness

### 4. Documentation
- Improve existing documentation
- Add translations
- Create tutorials or guides
- Expand methodology documentation

### 5. Bug Reports
- Report visualization issues
- Report data inconsistencies
- Report documentation errors
- Suggest improvements

## Getting Started

### 1. Fork the Repository
```bash
# Click "Fork" on the GitHub page
# Clone your fork
git clone https://github.com/YOUR-USERNAME/chickens-vs-people.git
cd chickens-vs-people
```

### 2. Create a Branch
```bash
git checkout -b feature/your-feature-name
# or
git checkout -b fix/bug-description
```

### 3. Make Your Changes
- Follow the existing code style
- Update documentation as needed
- Ensure data accuracy from official sources

### 4. Commit Your Changes
```bash
git add .
git commit -m "Brief description of changes

More detailed explanation if needed. Reference any related issues (#123)."
```

### 5. Push to Your Fork
```bash
git push origin feature/your-feature-name
```

### 6. Create a Pull Request
- Go to the original repository
- Click "New Pull Request"
- Select your branch
- Describe your changes
- Reference related issues
- Wait for review

## Code Style Guidelines

### HTML/CSS
- Use semantic HTML5 elements
- Keep CSS organized and commented
- Ensure responsive design
- Maintain accessibility standards

### JavaScript
- Use clear, descriptive variable names
- Comment complex logic
- Avoid global variables
- Use ES6+ features

### Data
- Use official sources (FAOSTAT, Eurostat, ONS)
- Document data sources
- Include year/date of data
- Note any data limitations

## Documentation Standards

### Markdown Files
- Use clear, concise language
- Include headers and subheaders
- Provide examples where helpful
- Link to relevant resources

### Comments in Code
```javascript
// Clear, concise comments
// Explain the "why", not the "what"
```

### Data Documentation
- Note source and retrieval date
- Include methodology notes
- Document any transformations
- List limitations

## Testing

Before submitting:

1. **Visual Testing**
   - Open `index.html` in multiple browsers
   - Test on mobile devices
   - Verify all data displays correctly

2. **Data Validation**
   - Check calculations
   - Verify source data
   - Cross-reference with official sources

3. **Documentation Check**
   - Proofread all text
   - Verify links work
   - Check formatting

## Pull Request Checklist

- [ ] Fork and branch created correctly
- [ ] Changes follow code style guidelines
- [ ] Documentation is updated
- [ ] Data sources are verified and documented
- [ ] No sensitive information included
- [ ] Tested in multiple browsers/devices
- [ ] Clear commit messages provided
- [ ] Unnecessary files not included

## Review Process

1. **Automated Checks**
   - GitHub actions verify file integrity
   - Links are checked

2. **Maintainer Review**
   - Code quality assessment
   - Data accuracy verification
   - Documentation review
   - Overall fit with project goals

3. **Merge**
   - Approved changes merged to main
   - Contributor credited in CHANGELOG

## Reporting Issues

### Bug Reports
Please include:
- Clear description of the issue
- Steps to reproduce
- Expected vs. actual behavior
- Browser/device information
- Screenshots if applicable

### Data Issues
Please include:
- Specific country and data point
- Source of discrepancy
- Link to official source
- Suggested correction

### Feature Requests
Please include:
- Clear description of feature
- Use cases and benefits
- Possible implementation approach
- Related issue references

## Project Philosophy

- **Accuracy**: Data from official, credible sources only
- **Transparency**: Document sources and methodology
- **Accessibility**: Ensure content is accessible to all
- **Collaboration**: Welcome diverse perspectives
- **Education**: Help others learn about global agriculture

## Code of Conduct

- Be respectful and inclusive
- Welcome diverse perspectives
- Provide constructive feedback
- Help others learn and grow
- Report harassment or violations

## Questions?

- Open an issue with your question
- Check existing documentation
- Review closed issues for similar questions
- Contact maintainers for clarification

## Recognition

Contributors are recognized:
- In CHANGELOG.md for each release
- In GitHub's contributor list
- In comments for code contributions
- As co-authors when substantial

Thank you for contributing! 🐔
